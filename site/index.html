Seven steps to a runnable eval.

Describe your feature; Evals Coach drafts each step, you edit it, and the outputs assemble as you go.

1

Describe your feature (or paste real outputs)

A sentence or two on what it does and the worst thing it could get wrong. If it's already live, paste a few real outputs too, and every later step gets grounded in what actually happened.

2

Confirm the evaluation question

It drafts the one decision your eval should inform. You adjust the wording until it fits.

3

Set good and bad

Turn “helpful” into observable must and must-not behaviours you can actually score.

4

Edit the test cases

It drafts a small representative set: normal, edge, adversarial and critical. If you pasted real outputs, half the cases are grounded in them. You edit any of it or add your own.

5

Approve the graders

For each criterion it picks deterministic, code, LLM-judge or human, and writes the judge prompt for you.

6

Choose the release gate

The one threshold that decides ship or hold, stated plainly instead of left implied.

7

Leave with a runnable eval

Everything assembles into an eval plan, a test-cases.csv, judge prompts and a calibration guide, ready for your team.

You walk away with the actual files.

Not advice about evals. Ready-to-import artifacts in formats your team already uses.

An eval plan

The decision, the criteria, the cases and the release gate, written up so anyone on the team can follow it.

test-cases.csv

A validated, importable test set you can drop straight into whatever eval tool your team already uses.

Judge prompts

Ready-to-run prompts for each LLM-graded criterion, matched to the good and bad you defined.

calibrate.md

How to spot-check each judge against 20 hand-labelled cases before it's allowed to gate a release. So you never ship on an uncalibrated score.

“The AI should be helpful and accurate.” That isn’t an eval.

Most AI features are shipped on vibes because turning fuzzy product intent into something measurable is genuinely hard. These are the traps Evals Coach helps you catch.

Vague quality words you can’t test

“Helpful”, “accurate”, “on-brand”. Until they become observable must / must-not behaviours, no grader can score them and no one can agree whether a run passed.

Evals that pass while the product fails

A green dashboard measuring the wrong thing is worse than none. Evals Coach hunts for what could score well while real users still get hurt.

Failures with no regression net

The same production incident keeps recurring because nothing turned it into a test case. Feed in the failures; get back regression cases, without inventing evidence.

An LLM judge nobody calibrated

An uncalibrated judge quietly gating your release is a coin flip in a lab coat. Get a path to check it agrees with human labels before it holds the gate.

Add Evals Coach to Claude.

It’s a Claude plugin. Install it once, in the app or in Claude Code, then ask it to build you an eval.

In the Claude app

Recommended

Desktop, web and Cowork. No terminal needed.

  1. 1
    Open Settings → Customize → Plugins
  2. 2
    Click Add, then Add marketplace
  3. 3
    Enter justshipai/evals-coach and confirm
  4. 4
    Click Install on Evals Coach, then enable it

Then ask it to build you an eval, in your own words.

Claude Code (CLI)

Terminal

Prefer the command line? Two commands in your terminal.

/plugin marketplace add justshipai/evals-coach /plugin install evals-coach@justshipai

Then ask it to build you an eval, in your own words.

Either way, Evals Coach builds you a private page that asks Claude from inside itself. Drafting runs on the Claude account of whoever opens that page, and they consent on first use.
